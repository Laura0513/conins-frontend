1. AMBITES - ENDPOINTS CRUD FALTANTES
   Los modales de Crear, Editar y Bloquear ya existen en frontend pero

   - POST   /api/ambientes
     Body: { nombre, tipo, capacidad, area_id? }

     Body: { nombre, tipo, capacidad, area_id?, activo }
   
   - POST   /api/ambientes/:id/bloquear
     Body: { fecha_inicio, fecha_fin, motivo }
     Accion: Guardar en tabla `ambiente_bloqueos`

2. ASIGNACIONES - HISTORICOS NO APARECEN
   PROBLEMA: Al desactivar una asignacion, desaparece de la lista en vez
   de moverse a la pestaña "Historicas".
   
   CAUSA: El JOIN con `asignacion_competencia` filtra solo competencias
   activas. Al desactivar la asignacion, sus competencias pasan a
   `activo = FALSE` y la consulta las excluye.
   
   SOLUCION: Cambiar INNER JOIN por LEFT JOIN en `findAll`, o crear
   endpoint separado `GET /api/asignaciones/historicas` con filtro
   `activo = FALSE`.

3. HORARIOS - EDICION DE BLOQUES DE DIAS
   El frontend ahora envia un array de dias al editar:
   
   PATCH /api/horarios/:id
   Body: { dia_ids: [1, 3, 5], hora_inicio, hora_fin, jornada_id, ambiente_id }
   
   LOGICA ESPERADA EN BACKEND:
   - Comparar dias actuales vs nuevos.
   - Eliminar registros de dias que se quitaron.
   - Actualizar registros de dias que siguen (cambiar hora, etc.).
   - Crear registros nuevos para dias que se agregaron.
   - Validar solapamiento para cada dia nuevo o modificado.

4. ENCODING UTF-8 - CARACTERES ESPECIALES DISTORSIONADOS
   PROBLEMA: Nombres con tildes (Analisis, Produccion, Logistica) se
   muestran con simbolos raros en frontend.
   
   ESTADO: Ya se agrego `charset: 'utf8mb4'` en db.ts, pero puede no
   ser suficiente si las tablas tienen collation diferente.
   
   VERIFICAR:
   - Collation de tablas debe ser `utf8mb4_unicode_ci`.
   - Si alguna tabla tiene `latin1`, convertirla:
     ALTER TABLE programas CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
