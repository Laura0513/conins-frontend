REQUISITOS FUNCIONALES — CONINS v7.0
Centro del Diseño y Manufactura del Cuero — CDMC SENA
Actualizado: 06 de Julio 2026 (49 RF — v7.0)


========================================================================================

Modulo AUTH — Autenticacion y gestion de cuentas

RF-01  El sistema debe permitir el registro de administradores (Subdirector,
       Coordinadora Academica y Asistente de Coordinacion) previa existencia
       del usuario en la base de datos.

RF-02  El sistema debe permitir el inicio de sesion seguro de administradores.

RF-03  El sistema debe permitir a los administradores editar su propia cuenta
       de usuario.

RF-04  El sistema debe permitir a los administradores recuperar y cambiar su
       contrasena.

RF-05  El sistema debe permitir a los administradores deshabilitar cuentas de
       usuarios con menor jerarquia.

RF-06  El sistema debe permitir a los administradores reactivar cuentas
       previamente deshabilitadas.

RF-07  El sistema debe permitir a los administradores cerrar sesion de forma
       segura.

RF-08  El sistema debe permitir el registro de instructores, de acuerdo a su
       rol, previa existencia en la base de datos.

RF-09  El sistema debe permitir el inicio de sesion seguro de instructores.

RF-10  El sistema debe permitir a los instructores editar su propia cuenta de
       usuario.

RF-11  El sistema debe permitir a los instructores recuperar y cambiar su
       contrasena.

RF-12  El sistema debe permitir a los instructores cerrar sesion de forma
       segura.

RF-13  El sistema debe permitir a los administradores crear y habilitar cuentas
       de nuevos usuarios (instructores), asignandoles correo, cargo y area
       antes de que puedan registrarse.

RF-46  El sistema debe permitir a los administradores registrar y consultar el
       tipo y numero de documento de identidad de cada usuario del sistema
       (CC, CE, TI o pasaporte), como campo adicional al registro de la cuenta
       de usuario.

Modulo INSTRUCTORES

RF-14  El sistema debe permitir a los administradores registrar y actualizar
       los datos especificos de los instructores: tipo de contrato (planta o
       contratista), tipo de area (tecnica o transversal) y vigencia del
       contrato, como complemento al registro de su cuenta de usuario.

RF-15  El sistema debe permitir a los administradores registrar y actualizar
       las competencias habilitadas para cada instructor segun su contrato
       vigente, de manera que el sistema pueda filtrarlas correctamente al
       momento de realizar asignaciones.

RF-16  El sistema debe permitir a los administradores registrar una novedad
       administrativa para un instructor activo (licencia, incapacidad,
       comision u otra), indicando el tipo de novedad, fecha de inicio, fecha
       estimada de regreso y un campo de observacion opcional, de manera que
       el sistema lo excluya de las opciones de asignacion mientras la novedad
       este vigente y lo reincorpore automaticamente al vencerse la fecha de
       regreso.

========================================================================================

Modulo FICHAS

RF-17  El sistema debe permitir a los administradores registrar fichas de
       formacion indicando el numero de ficha, fechas de inicio y terminacion,
       etapa (lectiva o productiva), y vinculandola a un programa, jornada y
       modalidad previamente registrados en el sistema.

RF-18  El sistema debe permitir a los administradores editar la informacion de
       una ficha registrada, incluyendo la actualizacion de su etapa cuando el
       grupo avance de lectiva a productiva.

RF-19  El sistema debe permitir a los administradores deshabilitar fichas de
       formacion sin eliminarlas fisicamente, conservando su historial de
       asignaciones y horarios.

RF-20  El sistema debe permitir a los administradores consultar y filtrar el
       listado de fichas por programa, jornada, etapa y modalidad.

RF-47  El sistema debe permitir a los administradores registrar una novedad
       administrativa de una ficha activa (comite de evaluacion, paro,
       actividad academica fuera del CDMC u otra), indicando el tipo de
       novedad, fecha de inicio, fecha estimada de regreso y un campo de
       observacion opcional, de manera que el sistema excluya la ficha de
       nuevas asignaciones de horarios mientras la novedad este vigente y la
       reincorpore automaticamente al vencerse la fecha de regreso.

========================================================================================

Modulo HORARIOS

RF-21  El sistema debe permitir a los administradores registrar horarios
       asignados a fichas, instructores y ambientes, asociados a una jornada.

RF-22  El sistema debe permitir a los administradores editar los horarios
       registrados en el sistema.

RF-23  El sistema debe permitir a los administradores deshabilitar horarios sin
       eliminarlos fisicamente, dejando registro del cambio.

RF-24  El sistema debe permitir visualizar la malla de horarios de una ficha o
       instructor en formato de grilla semanal, mostrando jornada, ambiente e
       instructor asignado por dia.

========================================================================================

Modulo ASIGNACIONES

RF-25  El sistema debe permitir a los administradores designar al instructor
       referente de una ficha activando el campo correspondiente en la
       asignacion (es_lider_ficha), y registrar informalmente el instructor
       referente de cada programa en la tabla lider_programa, como dato
       organizativo sin impacto en permisos del sistema.

RF-26  El sistema debe permitir a los administradores registrar que instructor
       actua como referente de cada programa de formacion, para efectos
       organizativos y de consulta.

RF-27  El sistema debe permitir a los administradores asignar competencias a
       instructores, validando que la competencia este habilitada para ese
       instructor segun su contrato.

RF-28  El sistema debe permitir a los administradores asignar ambientes a fichas
       e instructores, validando disponibilidad por jornada, horario y ausencia
       de bloqueo temporal vigente en el ambiente.

RF-29  El sistema debe permitir a los administradores registrar asignaciones
       provisionales de instructores a fichas o programas fuera de su area, con
       registro del autorizante, fecha y motivo.

========================================================================================

Modulo AMBIENTES

RF-31  El sistema debe permitir a los administradores registrar un bloqueo
       temporal de un ambiente, indicando la fecha de inicio, fecha de fin y
       motivo, de manera que el sistema lo excluya de las opciones de
       asignacion durante ese periodo y lo reincorpore automaticamente al
       vencerse la fecha de fin del bloqueo.

========================================================================================

Sistema / Administrador — MODULO ALERTAS, VALIDACIONES Y NOTIFICACIONES

RF-32  El sistema debe emitir una alerta cuando un instructor supere el limite
       de horas semanales permitidas segun su tipo de contrato, sin bloquear
       la asignacion.

RF-33  El sistema debe emitir una alerta cuando se intente registrar un horario
       en jornada nocturna o fin de semana para un instructor de planta, sin
       bloquear el registro.

RF-34  El sistema debe emitir una alerta antes de confirmar la asignacion
       cuando un ambiente ya este ocupado en la misma jornada por otra ficha,
       sin bloquear el registro.

RF-35  El sistema debe impedir que un mismo RAP quede asignado a dos
       instructores diferentes dentro de una misma ficha, validando esta
       restriccion antes de registrar cualquier asignacion.

RF-36  El sistema debe permitir registrar la suspension de un horario
       especifico, con campo de motivo obligatorio, dejando trazabilidad del
       cambio.

RF-37  El sistema debe verificar automaticamente que los cambios en horarios,
       jornadas, instructores o ambientes no generen conflictos con las
       asignaciones existentes, emitiendo una alerta si se detecta alguno.

RF-38  El sistema debe notificar al instructor cuando se le asigne, modifique
       o elimine una competencia o ficha, o cuando se registre una novedad
       administrativa sobre su cuenta, mediante una notificacion interna en el
       sistema y un correo electronico al correo registrado.

RF-39  El sistema debe notificar a la Coordinadora Academica y al Asistente de
       Coordinacion cuando ocurra un cambio de asignacion o se registre una
       novedad administrativa en un instructor del programa ADSO, o cuando se
       registre una asignacion provisional, mediante notificacion interna en el
       sistema.

RF-40  El sistema debe notificar a la Coordinadora Academica, al Asistente de
       Coordinacion y al Subdirector cuando se genere una alerta de carga
       horaria fuera de rango, una asignacion provisional, un bloqueo de
       ambiente, o una deshabilitacion de cuenta, mediante notificacion interna
       en el sistema.

Administrador / Instructor — MODULO CONSULTA Y VISUALIZACION

RF-41  El sistema debe permitir a los administradores consultar, visualizar,
       filtrar y buscar informacion de instructores, programas, competencias,
       ambientes, fichas, jornadas y horarios; incluyendo un panel de carga
       horaria semanal por instructor que muestre el total de horas asignadas
       comparado con el limite permitido segun su tipo de contrato.
       La Coordinadora Academica y el Asistente de Coordinacion ven el alcance
       ADSO; el Subdirector ve el CDMC completo.

RF-42  El sistema debe permitir a los administradores visualizar el estado de
       asignaciones activas, provisionales e historicas.

RF-44  El sistema debe permitir a los instructores consultar la informacion de
       las fichas, competencias, ambientes y horarios que tienen asignados,
       incluyendo el historial de notificaciones recibidas.

RF-45  El sistema debe permitir a los administradores exportar la malla de
       horarios de una ficha o instructor en formato PDF, para su uso en
       reportes, reuniones o evidencias de gestion.

MODULO SEGURIDAD Y TRAZABILIDAD

RF-48  El sistema debe filtrar los listados de horarios, fichas, asignaciones
       y alertas segun el rol del usuario autenticado, de modo que cada usuario
       acceda unicamente a la informacion correspondiente a su alcance: CDMC
       completo para Subdirector, programa ADSO para Coordinadora Academica y
       Asistente de Coordinacion, y solo sus fichas activas para Instructor.

RF-49  El sistema debe permitir categorizar cada bloque de horario mediante un
       tipo de actividad (clase, disponible, permiso/incapacidad, etc.),
       determinando si ese bloque suma o no a la carga horaria semanal del
       instructor segun el campo suma_carga_horaria del tipo de actividad.

RF-50  El sistema debe registrar y permitir consultar el seguimiento de
       resultados de aprendizaje (RAPs) por ficha, permitiendo marcar el estado
       de avance de cada RAP en cada ficha asignada.

RF-51  El sistema debe registrar automaticamente en una bitacora de auditoria
       cada operacion de creacion, modificacion o desactivacion realizada sobre
       los datos del sistema, asociandola al usuario autenticado que la realizo,
       y permitir a los administradores consultar este historial.
