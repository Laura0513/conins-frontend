2. PENDIENTES URGENTES (BLOQUEAN FUNCIONALIDAD)
========================================================================

A) Módulo Ambientes - Endpoints Faltantes
   El frontend ya tiene los modales de Crear, Editar y Bloquear listos,
   pero el backend no tiene implementados los endpoints para recibir los datos.
   
   Se necesitan:
   - POST   /api/ambientes          -> Crear ambiente
     Campos esperados: nombre, tipo (aula/taller/laboratorio), capacidad, area_id (opcional)
   
   - PUT    /api/ambientes/:id      -> Editar ambiente
     Campos esperados: nombre, tipo, capacidad, area_id, activo
   
   - POST   /api/ambientes/:id/bloquear -> Registrar bloqueo
     Campos esperados: fecha_inicio, fecha_fin, motivo
     Acción: Guardar registro en tabla `ambiente_bloqueos`

B) Módulo Asignaciones - Historicos no aparecen
   PROBLEMA: Cuando se desactiva una asignación, desaparece de la lista
   en lugar de moverse a la pestaña "Históricas".
   
   CAUSA PROBABLE: La consulta `findAll` tiene un JOIN con `asignacion_competencia`
   que filtra solo competencias activas. Al desactivar la asignación, sus
   competencias pasan a `activo = FALSE` y la consulta las excluye.
   
   SOLUCIÓN ESPERADA: Modificar la consulta para que traiga TODAS las
   asignaciones independientemente del estado de sus competencias, o crear
   un endpoint específico `/api/asignaciones/historicas` que filtre por
   `activo = FALSE`.

C) Encoding UTF-8 - Caracteres especiales distorsionados
   PROBLEMA: Los nombres con tildes (Análisis, Producción, Logística)
   se muestran con símbolos raros en el frontend (Anßlisis, Producci¾n).
   
   ESTADO: Se agregó `charset: 'utf8mb4'` en db.ts, pero puede no ser suficiente.
   
   SOLUCIÓN ESPERADA:
   - Verificar que la conexión MySQL use `SET NAMES utf8mb4` al iniciar.
   - Asegurar que las tablas tengan COLLATE utf8mb4_unicode_ci.
   - Verificar que el middleware de Express no esté alterando el encoding.

D) Módulo Horarios - Columna ambiente_id faltante
   PROBLEMA: El modelo `horario.model.ts` usa `h.ambiente_id` en las consultas,
   pero la tabla `horarios` en database.sql no tiene esa columna definida.
   
   SOLUCIÓN ESPERADA:
   Opción A: Agregar la columna al schema:
     ALTER TABLE horarios ADD COLUMN ambiente_id INT NULL AFTER competencia_id;
     ALTER TABLE horarios ADD CONSTRAINT fk_horario_ambiente FOREIGN KEY (ambiente_id) REFERENCES ambientes(id);
   
   Opción B: Si el ambiente se hereda de la ficha/asignación, ajustar las
   consultas SQL para hacer JOIN con `fichas` o `asignacion_competencia`
   en vez de buscar `h.ambiente_id` directamente.

3. SUGERENCIAS DE MEJORA (NO URGENTES)
========================================================================

A) Endpoint de Agenda por Ambiente
   Sería útil tener un endpoint `GET /api/ambientes/:id/agenda` que devuelva
   los horarios ocupados de un ambiente específico. Esto permitiría que el
   modal "Ver Agenda" en Ambientes muestre datos reales en vez de mocks.

B) Validación de Solapamiento en Horarios
   El frontend ya maneja las alertas de solapamiento, pero sería ideal que
   el backend devuelva un código de error específico (ej: 409 Conflict)
   cuando hay un cruce de horarios, para que el frontend pueda mostrar
   un mensaje más amigable.

C) Paginación en Listados
   Actualmente los endpoints devuelven todos los registros. Si la base de
   datos crece, sería bueno implementar paginación (?page=1&limit=20) en
   los endpoints de lista (instructores, fichas, asignaciones, horarios).

D) Endpoint de Consultas/Reportes
   El sidebar tiene un ítem "Consultas" que aún no tiene página ni backend.
   Sería útil definir qué consultas necesita el usuario (ej: carga horaria
   por instructor, ambientes disponibles por jornada, etc.) para implementar
   los endpoints correspondientes.

4. NOTAS TÉCNICAS ADICIONALES
========================================================================

- Los campos de fecha deben enviarse en formato YYYY-MM-DD.
- Los IDs deben enviarse como números, no como strings.
- El campo `es_lider_ficha` es booleano (true/false).
- El campo `competencia_ids` es un array de números [1, 2, 3].
- Las jornadas usan IDs: 1=Mañana, 2=Mixta, 3=Noche, 4=Virtual.
- Los días de la semana usan IDs: 1=Lun, 2=Mar, 3=Mié, 4=Jue, 5=Vie, 6=Sáb.
